# Video top-up reconciliation

Signed NewebPay callbacks remain the primary settlement path. These callback POSTs and the shared-secret studio service no longer refresh browser login sessions in the proxy; their handlers retain their existing signature/secret authentication.

Member summary reads now only return balance and history; they cannot bypass the background cooldown or repeatedly query abandoned orders. The read-only QueryTradeInfo request uses the payment service's own server-side merchant configuration. Verify the response CheckCode, exact merchant, order and amount; accept only TradeStatus=1 with no reported refund. Query SUCCESS by itself never proves payment. Errors/timeouts remain unconfirmed and do not grant points.

Confirmed payments use the existing settle_video_points_v1 database transaction used by callbacks, preserving ledger/balance atomicity and duplicate protection. Concurrent summary checks share a promise and a 30-second cache per server process. Cloudflare Cron runs every minute independently of browser activity. Each authenticated server-to-server batch checks up to six pending orders (three at a time), rotates a durable order-number cursor across all pending orders without an age cutoff, and retains that cursor after transport errors. Ordinary unpaid orders advance the cursor so they cannot starve later paid orders. The point dialog refreshes its displayed balance every 15 seconds while visible. A durable per-order cooldown is passed from the Worker to the payment service so unpaid orders are excluded until due: two minutes for fresh orders, ten minutes after fifteen minutes, and six hours after an hour. New checkouts get a 90-second window for the normal callback first. TRA10071 pauses background queries for four hours without blocking signed payment callbacks. There is no member-facing reconciliation button.

Sources: NewebPay NDNF manual sections 4.1.5, 4.1.6, 4.3 (https://www.newebpay.com/website/Page/content/download_api).
